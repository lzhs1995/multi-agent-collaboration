# 协作提效与任务收尾

本页补充[双向投递操作规则](efficient-bidirectional-collaboration-20261004.md)，
用于决定何时协作、如何归因等待、何时收尾。以完成用户任务的效率和质量为准；
文档维护本身不要求启动 executor，也不授权更换原会话或修改在途控制器。

## 先判断能否缩短完成时间

| 当前工作 | 执行方式 |
| --- | --- |
| 没有独立待办，或派单和核收成本高于工作量 | supervisor 直接完成，executor 可待命 |
| 有一项边界清楚、可独立核查的工作 | 一个已授权且携带上下文的 executor |
| 有两项互不依赖、不会争用写入或原生资源的工作 | 两个已授权 executor，各自任务包、nonce、输出目录 |
| executor 持续失效且已有自动接管授权 | 固定检查点并确认无并发写入后，supervisor 继续 SOLO |

先备好具体任务再握手。不要为了让两个窗口保持活跃而重跑已通过检查、
重复读相同证据或把同一个待办发给两人。共享源码只有一个写入者；
独立审查者先读取冻结输入，修改后只审必要增量。共享 UI 资源仍按原协议串行。
等待回调期间，supervisor 推进不依赖该结果的工作。

### 接续任务时先核实际归属

上下文摘要里的原 supervisor/executor 绑定可能与当前工具 caller 不同。
先把实时 caller、workspace UUID、原 role-map 和执行者当前任务对齐；
focused 面板、`EXECUTOR` 标题或同目录不能证明它属于本任务。
只读看到执行者正在处理另一份任务包时，记录“另有在途任务”，不插队派单、
不撤销它的任务，也不把它记作故障或空闲。原绑定在其他工作区时，保留原绑定，
按已有 SOLO 授权继续可独立推进的工作，不改环境身份或借用其他项目的执行者。

状态更新须说清当前使用零、一或两个执行者的具体原因，并区分“没有派单”、
“另有任务”、“身份不匹配”和“本任务执行失败”。只在下一次实际派单或已有阶段边界
重新核实可用性，不为证明 agent 活跃建立额外轮询；不能永久沿用过去的失败判断。

## 握手预算与准确归因

- 初始挑战直接提供绝对 pending receipt 和固定完整 SKILL 路径；握手只验证
  身份、通道及精确 ACK，不包含业务审计、全盘搜索或计划共识。
- 使用相位参数 `--handshake-timeout 600` 或更长预算；不要用泛化
  `--timeout` 覆盖各相位预算。600 秒是观察预算要求，不是强制等待：
  合格 ACK 一经观测就继续。健康的同任务握手复用。
- 分别保存 dispatch 提交、首次观测、ACK、检测终态时间及 budget_source、
  phase_minimum_seconds、ack_source。预算不足记
  `SUPERVISOR_BUDGET_TOO_SHORT`，不能记为 Claude 不响应。
- ACK 文本相同但 ack_line/ack_source/ack_observed_at 为空，只能说明检测器
  未观测到该 ACK，不能推定格式拒绝或执行者失效。先核原 task/nonce 的真实记录。
- 原绑定允许迟到 ACK 核收时只读恢复；已终态且不支持恢复时，保留失败，
  由原控制器在明确零输入或原发送已安全收口后建立后继。不要向旧 nonce 空转重发。

## 双向发送与回调收尾

prompt 和 callback 都须经原受保护 bridge，在每次写入前核 live UUID，
Enter 后核同一接收端的完整消息及原 marker。证据分开记：

1. 文字留在 compose：尚未证明提交。
2. queued：已排队，尚未证明消费。
3. 原生记录中的本次完整消息及关联后续活动：消费证据。
4. 由原绑定校验并发布的正式 receipt：传输核收。
5. supervisor 阅读报告与原件并裁决：业务接受。

按键返回成功、单独 marker、无关活动和报告文件存在不能跨级证明。
unknown/queued 只读核原 attempt，不能重贴、循环按键、删除 journal 或
改写冻结报告。补 Enter/Tab 只能由原 bridge 按既有严格条件执行，
不是人工看到 compose 就补键的许可。

executor 完成报告后调用原 callback 入口，由它判断输入条件；
不得额外等待 supervisor 的 busy=false，也不另建秒级 watcher。
若回调传输待核，supervisor 可先读取固定报告推进业务，保留“正式回执缺失”；
不能制造 receipt 或把维护等待扩大成所有工作停摆。旧任务的 disarm
仍遵循原操作规则的真实终态与证据要求。

## 有界恢复与安全接管

分别诊断 provider 故障、监督端预算不足、输入分类器拒绝、草稿保护、
排队和 ACK 漏观测。后三类不是模型失效，不能靠换模型、重启会话恢复。
原生 reconnect 或正常执行期间不插入外层重试，也不打断会话；
重试只在原尝试确已结束后遵循既有有限恢复协议。认证、欠费不盲重试。

持续不可用时沿用户已有授权：保留原会话和未决尝试，停止本阶段派单，
确认 executor 无在途写入，固定 checkpoint、nonce 和保护路径，由 Codex
接管。自审标 `solo_self_review`，不能冒称 Claude 独审。只在同一会话、
安全写入边界恢复协作；不能用清空上下文或替代 executor 绕过。

## 完成后及时收口

定点失败、必要增量回归、真实效果、用户验收分别留证。用户已验收的
局部故障即在账本结案，剩余主线另列；没有新变更或未决风险就不重跑旧矩阵。
状态更新说明完成了什么、尚缺什么、下一项具体动作，避免只堆测试数量。

经验进入仓库时只写可复用规则，不公开 Key、用户原日志或本机身份。
源码提交、CI、安装、客户端加载、真实投递及整体验收各自报告；
修改本页不代表新 hook 上线，也不需要重启正在工作的客户端。
