# Release 0.4.76

This maintenance release adds one original owned Word failure closeout and an
explicit read-only Claude model-context observer, and fixes file-only
registration ordering. Existing native receipts, queues, controllers and
historical input/recovery budgets retain their owners.

## File registration and stop evidence

After authenticated identity precommit, registration creates/verifies the
canonical 0700 original mailbox before live-state commit. A mailbox failure
therefore cannot publish an active enrollment that points to a missing channel.
Stop observations expose `operator_stop_reason`; already stopped historical
states are not rewritten to invent that reason.

## Original tracked-save failure

[Owned postnative closeout](word-postnative-closeout.md) binds the complete
published .75 controller, one closed five-stage native tracked round trip and
its original header-change failure. Read-only preview precedes an exact-SHA
original-actor transaction under the existing locks. Only the restricted
ticket's terminal status and a separate receipt change; all original bytes and
the consumed invocation remain. The input-identical save companion is pinned
and retained without claiming its producer or manuscript acceptance.

This does not solve a table-geometry or revision-preservation discrepancy.
It does not release the quarantined ordinary ticket or grant Zotero Refresh.
A later job needs a new reviewed scope and its own supported native validation.

## Separate model-context evidence

[Model context consumption](model-context-consumption.md) joins the complete
exact measured wrapper, canonical API content hash, matching request/response,
native hash/size and full-body Read, and all parallel tool results in a later
matching request/response. Cached blob version absence is supported only with
versioned real requests/responses/results. Partial, malformed or unsupported
chains remain unverified.

`MODEL_CONTEXT_CONSUMED` is an observation, not a renamed native-user receipt,
business acceptance, scientific acceptance or task/resource authority.
The checker has no automatic hook registration, no input and no original
attempt/receipt/queue mutation. Old u19/u20 runs, ACK order, children and accepted
denominators are not retroactively changed. Actual S2 consumers and complete
cost attribution remain private owner work.

## Supported ancestry, progress and skill entries

Identity-sensitive bridge, hook and original-actor calls use the direct
supported shell/rtk route. An outer Python `subprocess` orchestration is not an
authenticated tool proxy and cannot borrow the parent model's identity.
Do not weaken identity guards to accommodate that wrapper.

Native marker receipt, on-disk scoped acceptance, body reading and queued input
remain separate. Reconcile each uncertain original attempt only through its
complete original controller; no blind Enter or resubmission. Record actual
native timestamps, freeze time and gaps over 60 seconds with sample counts.
These observations and file sweeps do not wake a model or prove body reading;
this release installs no global blocking continuation hook.

New thesis scopes resolve and pin the complete canonical
`/Users/lzhs/.agents/skills/thesis-refiner/SKILL.md` source. A different local
Chinese-named copy is a historical local alias, not proof of canonical or active
hook adoption. Preserve old scopes and source pins; classification and a
document update do not overwrite that alias or change loaded clients.

## Compatibility and acceptance

The complete original .75 manifest/controller/scheduler hashes, its original
issuer/controller range and original capabilities are explicitly recorded.
No old code is imported or executed to learn trust; no historical issuer gains
future authority. The byte-identical ordinary-message driver compatibility
extends through .76, without granting replay or another recovery slot.

Private CLI controls cover real preview/transaction behavior, exact actor and
plan checks, bounded input, locked CAS, rollback and preserved original bytes.
A candidate run, source tests, independent review, CI, immutable installation and
actual original-actor closeout require their own evidence. An unavailable reviewer
does not become multi-agent consensus; authorized SOLO audit is labelled
`solo_self_review`.
