# cmux collaboration profile

Use for new work among independent native terminals and for registered cmux
tasks. Plain cmux remains supported; this profile is not limited to supervisors
or cross-workspace messages.

The [cmux outward skill](../skills/cmux-collaboration/SKILL.md) is the focused
entry for coordination between terminal teams. Nested Herdr teams use the same
common rules; organization at the outer layer does not change the actual
receiver's transport or grant access to an arbitrary inner pane.

Read the [common contract](collaboration-contract-core.md), then the existing
[verified delivery](verified-compose-delivery.md) and required supervisor or
executor protocol. Reuse healthy current-task bindings. Formal task dispatch,
callback settlement and resources continue through their supported controllers.
Do not enable continuing inquiries or proactive hooks without task enrollment.

Cross-workspace communication needs the designated endpoints and existing user
authority; it does not transfer old callbacks or file ownership. Send a milestone
or delta once, then observe/read/accept it separately. A file-only fallback stays
explicitly unconfirmed until there is actual receiver evidence.

Before terminal input, establish that the recipient is the intended native CLI,
not an outer Herdr/TUI container. Use the Herdr profile for an inner pane. This
restriction does not block a supported direct native-session channel.

Historical diagnostics and old callbacks retain their original release and
evidence. Do not reopen accepted research to test a transport improvement.
