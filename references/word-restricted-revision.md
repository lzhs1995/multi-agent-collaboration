# Initial Word revisions with a quarantined legacy ticket

An expired ordinary Word ticket can remain ACTIVE while an unknown foreign
draft has no lawful release proof. The ordinary broker then cannot issue a
fresh grant. An exactly approved original successor may use
`OWNED_REVISION_ROUNDTRIP` for a separately pinned initial manuscript job.
This is a distinct capability from the existing `OWNED_PDF_ONLY` lane.

The original 0.4.72 read-only PRE timeout has a separate exact-SHA closeout.
Unsaved bare document references remain unresolved, with unknown ownership
and no write permission. See [0.4.73](release-0.4.73.md).

The `word-restricted-disposition-v2` contract pins the original native user
approval, its complete preceding plan, the quarantined ticket/resource
preimages, both original process-group drain receipts and the accepted old
export. That plan must already cover a tracked manuscript, clean DOCX and
Word PDF while preserving foreign documents. PDF-only approval cannot gain
revision authority. Only the approved original successor may apply; a
maintenance contact does not transfer that resource authority.

Each `owned-initial-word-job-v1` has its own create-only disposition and one
request. It names the exact actor workspace, surface, pane and native thread,
an owned run directory, a pinned tracked input and the expected accepted and
rejected source-contract inputs. Output locations are fixed under that run:
`artifacts/tracked.docx`, `artifacts/accepted.docx`,
`artifacts/rejected.docx` and `evidence/accepted.pdf`.

The restricted plan pins every controller Python member, both existing PDF
service members, native PDF validators, lock inodes, directory inodes and a
unique stage id. It retains the 22GiB Word floor. The original queue tables,
foreign draft and legacy release predicates stay unchanged. PDF and revision
tickets share one FIFO and one ACTIVE/PENDING writer. The old PDF disposition
and its original-ticket uniqueness rule are preserved.

The broker selects the fixed `word_restricted_revision.py` child with `-BE`,
the original parent PID, process group, ticket, token and one nonce. The
child compiles pinned source bytes and accepts no arbitrary adapter, command,
environment, callback or macro. Native templates bind only uniquely staged
owned DOCX paths. Each copy is saved, closed, reopened read-only and closed
again. The tracked copy retains its revision headers; Word accepts all
revisions in the accepted copy and rejects them in the rejected copy. The
accepted output is then exported through the existing exact PDF templates.

When Word is absent, only an explicit `start_word_if_absent=true` plan permits
one fixed background launch. The running Zotero identity must remain the
same. A fresh Word process binding and native foreign-document baseline are
required after startup; restored foreign documents are never saved or closed.

A timeout or unconfirmed native stage keeps the ticket PENDING, retains
owned staging/evidence and never kills an application, resets the invocation
or retries. A possibly open owned document is recorded in the original Word
pending mechanism, including a PDF-stage timeout. A successful child still
requires the original group to drain, exact artifact SHA checks and unchanged
pre/post foreign observations before its restricted ticket can complete.

`COMPLETE_WITH_FOREIGN_UNKNOWN` proves the bounded owned operation only.
Source semantics and formatting remain `PENDING_PARENT_SOURCE_CONTRACT`;
the original manuscript owner must compare both native outputs with their
approved inputs. Final scientific acceptance remains false. This lane grants
no Zotero Refresh, ordinary resource release, unrelated document edit or
permission to replay old attempts. Installation, real native execution,
client adoption and overall efficiency need separate evidence.

Confirmed revision-stage receipts record the pre-call guard and actual
osascript process durations separately. These are measured stage windows;
they exclude startup, later verification and whole-task collaboration cost.
