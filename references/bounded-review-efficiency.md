# Make collaboration shorten delivery

Use existing context-bearing executors for independent work that advances the
user's accepted outcome. Agent activity, message counts and review volume are
not measures of completion. This is planning guidance, not a new runtime guard.

## Define a finite review before dispatch

Every review pack should name the decision it will unblock, exact input hashes,
allowed output directory, required checks and stopping condition. Scope the
review to concrete claims rather than “check everything again”. Classify each
finding as a demonstrated defect, an unresolved question or a suggestion, with
the evidence and practical consequence. Reaching the stopping condition ends
the review; optional investigations become a separate proposal, not silent scope.

Reuse an accepted review when its inputs, scope and relevant dependencies remain
unchanged. A repeated DONE is a notification, not a new review assignment. If
something changed, review the affected claims; retain the original evidence.
Do not equate acceptance of a limited review with acceptance of the whole task.

## Divide independent work; preserve one writer

With two authorized existing executors, assign separate task ids, nonces and
write roots. One may check dependency coverage while the other checks output
comparisons. The supervisor owns serial execution and final integration. Never
give both agents ownership of a shared application or the same deliverable.

Do not stack assignments behind active work or compaction. At the safe terminal
boundary, assign the next useful independent task. If none exists, standby is
appropriate. Do not manufacture repeated checks to keep both screens busy.

## Bound callback closeout

Keep report completion, submission, receiver consumption and report acceptance
separate. Enter is not proof of delivery. Preserve the original task, nonce,
report hash and send journal. A queued or uncertain send is observed without
another paste/key through the supported recovery interface.

Transport trouble must not become an unbounded second project for a reviewer.
Use the applicable bounded recovery procedure; then preserve unresolved evidence
and hand the transport issue to the supervisor. Do not introduce a second
watcher, wait indefinitely for supervisor idleness, alter a frozen report or
manufacture a receipt. Report acceptance alone does not disarm task guards:
close them only through the applicable verified terminal procedure.

The supervisor continues independent authorized work. Preserve current task
bindings and session identity. Authorized solo takeover requires the existing
safe write boundary; it is not permission to race an active executor.

## Measure benefit and report limitations

At an existing milestone, record which deliverable or blocking decision the
review advanced, whether it found a material defect, and avoidable coordination
cost. Do not add a polling system just to collect metrics. Reduce overlapping
review or switch the next assignment when coordination dominates useful work.

Use dated current evidence for availability. A past API error is not evidence
that both executors are currently unavailable; an active spinner does not prove
completion either. Do not promise permanent transport reliability from one
successful callback, an offline test suite or a documentation update.
