# 0.4.61: bounded progress and explicit continuity

Large original JSONL records no longer trap a256KiB polling cursor indefinitely.
The shared Tail accumulates bounded chunk pins and completes a record up to8MiB
only after verifying those chunks. It keeps partial/over-limit records and the
independent mailbox route. Exact record observations include device/inode,
offset, bytes and SHA of the original line ending. Source hashes and canonical
reply-body hashes remain distinct.

Native reception requires an actual original operator user record. Claude
`isMeta` Stop feedback is excluded even when it repeats a task marker. Tool/API
wrappers, queued attachments, assistant echoes and subsequent continuation
messages do not prove exact original task-wire reception. Do not rewrite old
journals or replay an uncertain message to compensate for a missing receipt.

Automatic terminal inquiries inspect authenticated original Codex terminal
outcomes. Three distinct same-class native failures, or one authentication or
billing failure, open a circuit. Native API success rearms it; file inquiries
continue. The gate never changes providers, credentials or a Goal and never
counts queue observations as API failures. A vanished original agent replaced
by a shell is refused before input. Explicit messages retain their ordinary
authorized route and draft protection.

Before native input or original reconciliation, the saved V2 body must still
have its original canonical identity and exact bytes. Notice reception, full
body reading and business acceptance remain separate evidence.

`register-successor` creates a read-only plan for the authenticated original
executor. Apply requires its exact plan hash and task-bound user authority,
archived state/enrollment/stop preimages and last-moment original-executor and
native-target checks. A different supervisor thread on the same surface needs
explicit registration too. The recoverable transaction enrolls file-only
inquiries and transfers neither pending messages nor callback/shared-write or
reservation ownership. Installation alone changes no old episode.

`work-checkpoint` stores exact, immutable original-executor work evidence and
monotonic status/unit/issue progress. A repeated hash is idempotent. Directory
sync recovery completes the original receipt before state commit and refuses
epoch regression. Parent acceptance is always `UNMEASURED`; an inquiry counter
is never a work-progress measure.

The complete reviewed0.4.60 historical issuer/controller range is retained
under its original pins, without extending its capabilities. Newly required
dependencies are pinned in the current controller. Hook launchers remain-BE.

Codex-unavailable peer work is bounded to two submitted, unreviewed packages per
author. At the limit, cross-review, pre-register future scope or use the original
60-second inquiry. Recovered excess packages remain valid and must be drained.
Peer completion does not grant original-supervisor or scientific acceptance.

Source tests, CI, release, installation, original-client adoption, automatic
hooks, native reception, full reading, acceptance and real consume/rearm cycles
are independently measured. Offline controls do not prove a live cycle.
