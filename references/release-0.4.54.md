# 0.4.54: Existing terminals may share a pane

Ordinary messages, broadcast discovery, exact maintenance contact and formal
preflight admit distinct existing terminal surfaces in one pane. The new gate
records versioned channel evidence and checks every participant against its
workspace proof. The actual side-panel layout remains a separate diagnostic.

Each surface and native session remains distinct. Preserve designated scope,
workspace and pane pins, native Codex input, Claude drafts, original attempts
and pane/target input locks. Sharing a pane does not authorize a new session or
shared-file writes. Old gates retain their original controller and contract.
See [existing terminal tabs](existing-terminal-tabs.md).

All 315 immutable predecessor members were statically verified against commit
`e76744c3dfa7e86f08e9d828c9a64f86a1023dad` and manifest
`b28ca93e025a9e0fe01fc2da2d21d10661f08a7a4f3341e592378a38958bab16`.
The original 20-controller issuer scope and explicit reservation-inquiry
capability remain unchanged; earlier issuers receive no future authority.
Existing .52 episodes keep their registration and consumption identity.

Source tests, publication, installation, actual automatic hooks and native
receipt remain separate evidence. This release does not repair a missing
Codex control endpoint or prove a business task completed.
