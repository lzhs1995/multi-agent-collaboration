# Owned PDF work while a foreign Word draft remains unknown

`scripts/word_restricted_broker.py` maintains separate disposition and FIFO
ticket tables in the original queue database. It never edits the original
`tickets` or `resources` tables. The expired original ACTIVE ticket remains
quarantined, and every restricted operation verifies its exact preimage and
resource mapping. Older generic brokers cannot find the new restricted tickets
or use this disposition as an ordinary resource release.

An administrative preview reads the exact original native user approval and its
preceding plan by path, device/inode, record boundary and SHA256. This first
supported scope is an approved successor plan explicitly preserving the unknown
foreign draft. Apply also authenticates the designated original administrator
and requires the exact preview SHA. In this first supported scope, only the
explicitly approved successor may be that administrator; a maintenance
coordinator does not acquire this task's resource authority. It preserves both original terminal
receipts, the accepted export/input/PDF and staging cleanup. An old null PGID
alone does not establish the boundary. Current original-group or Word pending
evidence refuses admission.

The new authenticated successor uses a distinct task plan and ticket. The plan
pins all controller Python members, the supported Word PDF service/runtime,
the exact native PDF validators, new input/output/evidence paths and both
existing Word and desktop-focus lock inodes. Keep the original 22GiB Word
admission floor. This lane grants neither citation refresh nor ordinary
Word/Zotero resource ownership.

The fixed `word_restricted_pdf.py` broker child accepts no arbitrary command,
environment, callback, service injection or alternate script. It compiles the
pinned controller and service source bytes directly, ignoring unchecked pyc
caches, and starts with `-BE`. Parent PID, process group, nonce, lease, input,
source closure, lock inodes and running Word/Zotero process births are checked
again at native work boundaries.

Each app operation must match one exact supported PROBE/PREFLIGHT/OPEN/
RESOLVE_PATH/EXPORT/CLOSE template. Mutating templates bind only the newly
staged absolute owned path. The lane contains no global activation, alert
change, save/close of foreign documents or Zotero macro. Read-only pre/post
inventory tolerates missing references as `MISSING` and saved state as
`UNKNOWN`; it never changes those values to zero. Actual metadata changes,
modal/sheet uncertainty, native failures and timeouts preserve the pending
ticket and invocation. They never kill an application or authorize a replay.

Successful owned cleanup and matching pre/post observations finish only the
restricted ticket as `COMPLETE_WITH_FOREIGN_UNKNOWN`. The original ticket
remains ACTIVE, `legacy_released=false`, `documents_verified=false`, and Zotero
internal idle remains unverified. A later restricted task may proceed in FIFO
order. This lane cannot complete a true-citation requirement; that needs its
separate complete native authority and lifecycle.

Private queue, source-load and native-template tests verify implementation
boundaries. They do not establish real Word delivery, client-wide adoption or
dissertation scientific acceptance. Apply and live use retain separate receipts.
