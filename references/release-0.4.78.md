# Release 0.4.78

This release adds a separate prospective sequential model-context observer for
the measured Claude 2.1.303 notice, hash and complete Read chain. See
[the contract](model-context-sequential.md). The original observer, native-user
reader, message driver, queues, identity and recovery budgets remain unchanged.

The new observer follows every immediate request, includes every actual parallel
result, and verifies canonical whole-batch hashes, unique tool/response identities,
successful measured stdout, the exact full body and the matching later response.
The exact R76 Bash measurement form is supported as data; its expected-SHA echo
provides no evidence. It never executes transcript commands.

Canonical file paths, original inode, metadata, prefix/tail and stable byte
rereads remain required. APFS device changes are recorded separately in this
new class; they do not migrate or repair original native receipts.

Source controls cover complete sequential and same-batch joins, omitted/failed
parallel results, skipped requests, duplicates, malformed reads, false echoes,
version/compaction transitions, partial/bounded snapshots, current input changes,
APFS device drift, retained-inode replacement and the public zero-input CLI.
The frozen real R76 two-batch sample is reproduced without another live window,
provider request, lane input or original-attempt mutation.

The byte-identical protected ordinary-message driver is explicitly recognized
for .78 by its existing exact SHA. Future driver versions remain refused.
This does not grant another original recovery slot.

An immutable source package, installation, active loading, a prospective live
consumer, task adoption, scientific acceptance and efficiency benefit require
their respective evidence. Publishing this source does not change the original
u21 NOT_ACCEPTED or original A UNVERIFIED outcome, or omit failed-request cost.
